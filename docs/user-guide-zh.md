## 1. 这是什么

bili-transcriber 是一个**纯本地**的视频 / 音频转写桌面工具。

给它一条链接，它自己完成「下载音频 → 转码 → 本地 AI 转写 → 导出字幕」四步，最后给你三份文件：`.srt`（带时间戳字幕）、`.txt`（纯文本）、`.md`（带时间戳的 Markdown）。

**它和在线转写服务的关键区别：**

| | bili-transcriber | 在线转写服务 |
|---|---|---|
| 音频是否上传 | 不上传 | 上传到对方服务器 |
| 是否需要账号 | 不需要 | 通常需要 |
| 是否有次数限制 | 无 | 通常有 |
| 断网能否用 | 模型下载后可 | 不能 |
| 费用 | 免费 | 按分钟计费 |

代价是**首次要下载模型**（Whisper `large-v3-turbo` 约 1.6 GB），以及转写速度取决于你的显卡。

## 2. 安装

### 2.1 系统要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（本项目只在 Windows 上验证过） |
| 显卡（可选） | NVIDIA + CUDA 12.x；没有也能用，走 CPU |
| 磁盘空间 | 程序约 700 MB + 模型 1.6 GB + 你的产物 |
| 内存 | 建议 8 GB 以上 |
| FFmpeg | **无需安装**，程序内置静态版 |

### 2.2 四种形态选一个

**安装版（推荐普通用户）**

双击 `bili-transcriber-setup-{版本}.exe`，按向导下一步到底。桌面和开始菜单会生成快捷方式，之后从快捷方式启动。

**便携包**

把 `bili-transcriber-portable-{版本}.zip` 解压到任意目录（例如 `D:\Tools\BiliNote\`），双击里面的 `bili-transcriber.exe`。

优点：不写注册表、不装依赖，整个文件夹拷到 U 盘就能在另一台机器上用。

注意：解压后**不要单独移动 exe**，它依赖同目录下的一堆文件。

**单文件版**

直接运行 `bili-transcriber-single-{版本}.exe`。只有一个文件，方便临时用。

代价：每次启动要先把自己解压到临时目录，首启比较慢；且为 CPU 模式，想要 GPU 提速请用前两种。

**源码模式（开发 / 二次开发）**

```powershell
python -m venv .venv
.venv\Scripts\pip install -e .
.venv\Scripts\python -m app.main
```

需要 Python ≥ 3.11。

### 2.3 GPU 加速包（可选，但强烈建议）

安装版和便携包**默认用 CPU 推理**。如果你的机器有 NVIDIA 显卡，装上这个包会快很多：

1. 下载 `bili-transcriber-gpu-{版本}.zip`（约 1.3 GB）。
2. 解压到 `%LOCALAPPDATA%\Bili Note\gpu\` —— 在资源管理器地址栏输入这个路径回车即可打开。
3. **检查路径层级**：解压后应存在 `gpu\nvidia\cublas\bin\cublas64_12.dll`。zip 里保留了 `nvidia/<包>/bin/` 结构，**照原样解开，不要压平**——程序按这个结构定位 4 个 DLL 目录（cublas / cudnn / cuda_runtime / cuda_nvrtc）。
4. 重启应用。

程序会自动检测并注册这些 DLL，**不需要配环境变量，也不需要单独装 CUDA Toolkit**。

装错了不会报错 —— 程序会静默回退 CPU，只是慢。所以装完建议去设置页看一眼「设备」附近的硬件提示。

## 3. 第一次启动

启动后会做三件事：

1. 启动本地服务，默认监听 `http://127.0.0.1:8765`。
2. 自动用默认浏览器打开这个地址。
3. 关掉浏览器标签页**程序不会退出**，它退到系统托盘继续待命。

**托盘图标右键**有两个选项：「打开主窗口」「退出」。要真正关掉程序，请用「退出」。

### 端口冲突

如果 8765 被别的程序占了，启动会失败。换端口：

```powershell
$env:BILI_PORT = "9000"
```

然后重新启动。用源码模式时这样设；用安装版时可以先开一个 PowerShell 设完环境变量，再执行 exe 的完整路径。

### 「已有实例在运行」

程序做了**单实例保护**。重复双击快捷方式时，第二个进程会：

1. 发现已有实例 → 把浏览器指向已有窗口的地址 → 自己退出。

所以看到「已有实例在运行，已打开现有窗口」不是报错，是设计如此。这样做是为了防止两个进程同时处理同一批任务、互相删对方的中间文件。

### 原生窗口模式（实验）

默认用浏览器打开，兼容性最好。想用独立窗口（需要系统里有 WebView2）：

```powershell
$env:BILI_FORCE_NATIVE = "1"
```

单文件版开原生窗口可能白屏，所以默认不开。

## 4. 任务页

### 4.1 提交链接

在输入框粘贴链接。支持：

| 平台 | 链接形态 | 免登录 |
|---|---|---|
| B 站 | `bilibili.com/video/BVxxx`、`b23.tv/xxx` 短链、带 `?p=2` 的分 P、合集 | ✅ |
| 抖音 | `v.douyin.com/xxx` 短链、完整视频页 | 精选内容需 Cookie |
| 小红书 | `xiaohongshu.com/explore/xxx` | 部分需 Cookie |
| 快手 | `v.kuaishou.com/xxx` 分享链 | ✅（自研解析） |
| YouTube | `youtube.com/watch?v=xxx`、`youtu.be/xxx` | 需代理 + 可能需 Cookie |

> 微信视频号链接会被**主动拦截**并提示改用「本地上传」——视频号没有可用的免登录直链。把视频下载下来再选文件转写即可。

点「添加」后，系统会先**探测**这条链接 —— 这一步会告诉你它到底是单 P、多 P 还是合集。探测结果会展开成**若干条独立任务**：多 P 视频有多少 P 就是多少条任务，合集同理，每条任务单独一行。

**输出目录的归属规则**：属于同一个合集 / 多 P 的分 P **共享一个目录**（`{BV号}_{合集标题}/`），靠文件名里的 `_P01`、`_P02` 后缀区分——这样整季课程的字幕会规规矩矩待在一起。单 P 视频则是 `{BV号}_{视频标题}/`。

> 探测失败最常见的原因是网络或 Cookie，失败信息会直接显示在任务行上。

### 4.2 状态含义

| 状态 | 含义 | 正常耗时 |
|---|---|---|
| `queued` | 已入队，等空闲的工作线程 | 通常瞬间 |
| `downloading` | 正在下载音频（开了讲义时下视频流） | 取决于网速与视频长度 |
| `converting` | FFmpeg 转成 16 kHz 单声道 WAV | 几秒到几十秒 |
| `transcribing` | 模型推理中，最慢的一步 | 见下方说明 |
| `extracting` | 提取讲义关键帧（仅开启讲义时） | 与视频长度相关 |
| `saving` | 写 SRT / TXT / MD | 瞬间 |
| `done` | 成功 | — |
| `failed` | 失败，行上有错误原因 | — |
| `cancelled` | 你手动取消 | — |
| `paused` | 你手动暂停 | — |

**转写耗时参考**（10 分钟中文视频）：

| 配置 | 大约耗时 |
|---|---|
| RTX 3060 + `large-v3-turbo` + `float16` | 30~60 秒 |
| RTX 3060 + `large-v3` | 1.5~2 分钟 |
| CPU（i7 级）+ `large-v3-turbo` + `int8` | 8~15 分钟 |
| CPU + `sensevoice` | 2~4 分钟 |

### 4.3 每行能做什么

任务行右侧有三个按钮：

- **打开所在文件夹** — 直接定位到产物目录。如果产物被删了，会依次降级：先试文件，再试父目录，最后试输出目录，不会弹「找不到」的死路。
- **重新运行** — 重跑这条任务。
- **取消** — 停掉正在跑的任务。

关于「重新运行」，有个重要特性：**已完成的步骤不会重做**。音频下载过就复用，WAV 转码过就复用。所以：

- 转写阶段失败了 → 重跑只重做转写，不用再下载。
- 想换模型重跑 → 也会复用音频，直接重新推理。

只有当中间产物被你手动删了，才会重新下载。

### 4.4 运行日志

任务页下方有一个实时滚动的日志区。它会显示：

- 当前在做什么（下载第几 P、转写第几块）
- 错误原因（不是「失败」两个字，而是真实异常）
- 模型加载、GPU 回退等提示

遇到问题先看这里。它比任何 FAQ 都准。

### 4.5 多任务并发

程序默认 **2 路并发**做下载和转码（设置页可改 1~6），但**转写是严格串行的**。

为什么转写要串行：多个任务同时往同一块显卡塞数据会直接把显存打满，报 `CUDA out of memory`，结果全都失败。串行虽然看起来「一次只干一件事」，但总体更快也更稳。

实际体验：任务 A 在转写时，任务 B 可以同时下载。前一个转写完，后一个的音频已经准备好了，几乎无缝衔接。

## 5. 转写本地文件

除了链接，也能直接转写你电脑里的音视频文件。有两个入口：

### 5.1 选择文件（推荐）

点「选择文件(推荐,立即转写)…」，弹出**系统原生文件选择框**，选完立即开始。

特点：

- **零拷贝**：程序直接引用你选的那个文件的原始路径，不复制、不上传。
- 秒提交：选完就开始探测，不像上传那样要等文件传完。
- 大文件首选。几个 GB 的录屏也没问题。

### 5.2 浏览器上传

点「浏览器上传」，选文件后它会走 base64 传到本地服务。

什么时候用：**用手机或另一台电脑访问这台机器的网页时**。这种情况下原生文件框用不了（它只能选本机的文件），只能走上传。

注意：

- 上传的副本保存在 `uploads/` 目录，**程序不会自动清理**，需要你自己定期删。
- 大文件明显慢，因为 base64 会让数据膨胀约 33%。1 GB 的文件要传很久，属正常现象。

### 5.3 支持格式

```
视频: mp4  mkv  mov  avi  webm  flv  wmv
音频: mp3  m4a  wav  ogg  opus  flac  aac
```

其余格式请先用 FFmpeg 转换。

### 5.4 本地文件的产物目录

目录名是 `{文件名}_{哈希}/`，哈希由「绝对路径 + 文件大小 + 修改时间」算出，用来区分同名但内容不同的文件（比如 `会议记录_` 后面跟一串十六进制）。文件名主干取原文件名，和平台视频的目录不会混。

## 6. 历史页

历史页是**已完成任务的索引**，存在本地 SQLite（`data/history.db`）。

能做什么：

- 按状态筛选（只看失败、只看完成）。
- 按标题关键字搜索。
- 每行打开所在文件夹 / 重新运行。

**清空历史只删索引，不删产物文件。** 产物在你的输出目录里，需要自己去删。

历史记录以 `media_id` 为主键（B 站是 `BV号_p分P`，其他平台是 `yt_` / `dy_` / `xhs_` / `ks_` 前缀 + 视频 id）。同一个视频重复转写不会产生两条记录，会覆盖更新。

## 7. 设置页

所有设置存在 `data/settings.json`。设置页有「恢复默认」一键还原。

**保存时会校验**：填了不合法的值会被直接拒绝并告诉你原因，不会把错误配置写进文件 —— 避免下次启动直接崩。

### 7.1 引擎与模型

| 设置 | 可选值 | 建议 |
|---|---|---|
| 识别引擎 | `whisper` / `qwen3-asr` / `sensevoice` | 默认 whisper |
| 转写模型 | 随引擎变化 | whisper 用 `large-v3-turbo` |
| 设备 | `auto` / `cuda` / `cpu` | 有 N 卡就 `auto` |
| 计算精度 | `auto` / `float16` / `int8_float16` / `int8` | 显存不足改 `int8` |
| 语言 | 空 / `zh` / `en` | 中文视频填 `zh` 更快更准 |

切换引擎后，模型下拉框会**自动换成该引擎的模型列表**，不会出现「引擎是 whisper 但模型是 Qwen」这种非法组合。

### 7.2 输出与缓存

| 设置 | 说明 |
|---|---|
| 输出目录 | 产物放哪。可填相对路径（相对程序目录）或绝对路径，如 `D:\个人用` |
| 保留音频 | 关掉后转写完就删原始音频，省空间 |
| 图文讲义 | 见 [7.5](#75-图文讲义) |
| 模型目录 | 默认 `%LOCALAPPDATA%\Bili Note\models`。可指定别处，或放手动下载的模型包 |
| 并发数 | 下载 / 转码的并发线程数，1~6，默认 2 |

### 7.3 网络与登录

| 设置 | 说明 |
|---|---|
| 浏览器 Cookie | 下拉选 Chrome / Edge / Firefox / Brave / Opera / Vivaldi。程序会去读该浏览器已登录的 Cookie。**使用前请先在该浏览器登录目标网站** |
| cookies.txt | Netscape 格式的 cookie 文件路径。**优先级高于浏览器 Cookie** |
| 网络代理 | 如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`。YouTube 等境外平台需要 |

什么时候要 Cookie：

- 抖音「精选」类内容（普通视频通常不需要）
- 部分 YouTube 视频（需要登录确认年龄 / 会员）
- B 站高码率或大会员内容

cookies.txt 怎么来：浏览器装一个导出 cookie 的扩展，导出 Netscape 格式，存到本地，把路径填进设置。

### 7.4 模型管理

设置页有「检测模型」按钮，会扫描模型目录并告诉你：

- 哪些模型已就绪（文件完整）
- 哪些模型缺文件（下载不完整，需要重下）
- 每个模型大概占多大

如果提示缺失，最省事的做法是**删掉那个模型目录**，让程序重新下载。

### 7.5 图文讲义

开启后，程序会尝试识别视频里的 **PPT 翻页**，生成一份带截图的讲义。

产物是 `{标题}.notes.md` + `{标题}_frames/` 目录。每一页长这样：

```
## [00:03:21] 第三部分：架构设计

![slide](标题_frames/slide_003.jpg)

（00:03:21 - 00:04:05 期间的字幕内容）
```

几个要点：

- **B 站任务会改下视频流**（不是纯音频），文件体积明显变大。目的是为了能抽帧。
- 本地上传 / 快手的任务，如果原文件本身是视频，直接抽帧，不需要额外下载。
- **纯音频文件自动跳过讲义**，不报错。
- **讲义生成失败不影响转写结果**。字幕照常输出，只是没有讲义。

什么时候值得开：技术分享、公开课、讲座 —— 凡是「屏幕上有字」的内容。纯口播的播客、访谈，开了纯属浪费。

### 7.6 AI 调用与命令行（通道开关）

设置页往下有一节「AI 调用与命令行」，两个开关**默认都开**：

| 开关 | 打开时 | 关掉后 |
|---|---|---|
| 允许命令行（CLI）调用 | 脚本 / 终端可调 `--cli` | 直接返回错误说明，退出码 **3** |
| 允许 MCP 调用 | AI 软件可调 `--mcp` | 服务拒绝启动，退出码 **1**，原因写 stderr |

什么时候关掉：

- 你只用桌面端，不想让任何外部程序动转写能力（少一个入口就少一处风险）；
- 排查问题时想排除「是不是某个 AI 客户端在偷偷跑任务」；
- 机器要临时借人用。

几条必须知道的行为：

- **只影响新进程**。开关只管「之后启动的 CLI / MCP」；已经连上的 AI 客户端要重连才生效。桌面端自身永远可用。
- **只能从桌面端改**。`--set enable_cli=false` 和 MCP 的 `update_settings` 都会被拒绝（提示「请在桌面端设置页修改」）—— 这是故意的：被提示注入的 AI 不能给自己开门。
- **改完要保存**。和别的设置一样，勾选后点「保存设置」才落盘。
- **进不去怎么办**：如果 CLI 被关了又需要用，编辑 `data/settings.json`，把 `enable_cli` / `enable_mcp` 改成 `true` 即可（文件是普通 JSON）。

同一节里还有一个「MCP 客户端配置」折叠面板，展开是可直接复制的配置片段，命令路径按当前形态自动填好，点「复制配置」就进剪贴板。

### 7.7 恢复默认

「恢复默认」会把所有设置重置为出厂值，包括输出目录回到 `output/`，两个通道开关也回到「开」。

注意：它**不会**删你的模型、历史、产物。

## 8. 输出文件

### 8.1 目录结构

每个视频（每条任务）一个独立目录：

```
{输出目录}/{平台ID}_{标题}/
├── {标题}.srt              # 带时间戳字幕
├── {标题}.txt              # 纯文本稿
├── {标题}.md               # 带时间戳的 Markdown
├── {标题}.m4a              # 原始音频（设置里可关掉保留）
├── {标题}.notes.md         # 图文讲义（开启后才生成）
└── {标题}_frames/          # 讲义关键帧
    ├── slide_001.jpg
    └── ...
```

目录名里的「平台 ID」：B 站是 `BV1xx411c7mD`（合集则用合并集标题），其他平台是 `yt_xxx` / `dy_xxx` / `xhs_xxx` / `ks_xxx`。前缀的作用是防止不同平台的视频 id 撞车。

**多 P / 合集的文件名后缀**：当一条视频包含多个分 P 时，文件名主干会加上 `_P01`、`_P02`……（两位补零）。这是必要的——B 站合集里各 P 标题经常重复，不加后缀会直接互相覆盖。

标题会做文件名安全处理（去掉 `\ / : * ? " < > |` 等非法字符，过长会截断）。

### 8.2 三种字幕格式怎么选

**`.srt`** — 标准字幕格式，几乎所有播放器和剪辑软件都认。

```
1
00:00:03,120 --> 00:00:06,480
大家好，今天我们聊一下这个架构

2
00:00:06,480 --> 00:00:09,200
先说结论，它分三层
```

适合：导入剪映 / Premiere / DaVinci 做字幕轨、上传到视频平台、用 Aegisub 精修。

**`.txt`** — 纯文本，一句一段，没有时间戳。

适合：直接读、喂给 AI 做摘要、导入笔记软件。

**`.md`** — Markdown，每段前带 `[hh:mm:ss]` 时间戳。

```markdown
## 大家好，今天我们聊一下这个架构

[00:00:03] 大家好，今天我们聊一下这个架构
[00:00:06] 先说结论，它分三层
```

适合：在 Obsidian / Typora 里读、需要边读边定位到视频时间点。

### 8.3 原子写保护

所有产物都是**先写临时文件再原子替换**，并且带权限冲突重试。

实际意义：如果写文件时杀毒软件正好在扫这个目录、或者你正在用别的程序打开这个文件，写入会重试而不是直接失败，也**不会留下半截文件**。

## 9. 三个识别引擎怎么选

| | Whisper | Qwen3-ASR | SenseVoice |
|---|---|---|---|
| 模型 | `large-v3-turbo` / `large-v3` / `medium` / `small` / `base` / `tiny` | `Qwen3-ASR-0.6B` / `1.7B` | `SenseVoiceSmall` |
| 中文准确率 | 很高 | 很高（口语更稳） | 中等 |
| 英文准确率 | 很高 | 中等 | 中等 |
| 标点 | 好 | 好 | 一般 |
| GPU 加速 | ✅ CUDA（ctranslate2） | ✅ 有 GPU 更快 | ❌ 主要靠 CPU |
| CPU 速度 | 慢 | 慢（1.7B 更慢） | 快 |
| 模型体积 | 1.6 GB（turbo） | 0.6B ≈ 1.2 GB / 1.7B ≈ 3.4 GB | 约 250 MB |

**怎么选：**

- **默认就用 Whisper `large-v3-turbo`**。综合最稳，有 GPU 时速度也够快。
- **准确率优先、不在乎时间** → Whisper `large-v3`（比 turbo 略准，明显更慢）。
- **中文口语、访谈、方言口音重** → Qwen3-ASR `1.7B`。它对不标准的普通话容忍度更高。
- **老机器 / 只有 CPU / 想快速粗看** → SenseVoice。几百 MB，CPU 也能跑，代价是标点和专有名词差一些。
- **显存小（4 GB）** → Whisper `medium` + `int8`，或 Qwen3-ASR `0.6B`。

**关于 VAD**：默认开启，作用是先检测哪里有人声，跳过静音段。副作用是纯音乐 / 唱歌视频可能被判定为「无人声」而输出空结果。程序遇到这种情况会**自动关闭 VAD 重试一次**。如果重试后还是空，那多半视频里真的没人说话。

## 10. 命令行与 AI 调用

除了点界面，还有两种无界面用法。

### 10.1 命令行

源码模式装完后，`Scripts\` 下有 `bili-transcriber-cli`。打包版没有独立 CLI 文件，用分发前缀 `bili-transcriber.exe --cli <参数>`（在进 GUI 之前就被拦下，不会开窗口）：

```powershell
# 提交并等待，输出 JSON
bili-transcriber-cli "https://www.bilibili.com/video/BV1xx411c7mD" --json

# 只提交不等待
bili-transcriber-cli "https://..." --no-wait

# 查任务
bili-transcriber-cli --list --json --limit 10
bili-transcriber-cli --status BV1xx411c7mD_p1 --json

# 取产物文本
bili-transcriber-cli --result BV1xx411c7mD_p1 --format md --max-chars 20000

# 改设置
bili-transcriber-cli --set engine=sensevoice --set device=cpu

# 预加载模型（等到就绪才退出）
bili-transcriber-cli --prewarm --json
```

完整参数见 README 的「命令行参考」一节。

`--no-wait` 提交的任务不会丢：**下次启动桌面端会自动续跑**所有遗留的进行中任务，包括半路被强杀的那种。

退出码约定：

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 任务失败 / 执行错误（含参数值非法） |
| 2 | 参数错误（缺值、互斥参数冲突） |
| 3 | 通道已在设置页关闭 |

另外，`--json` 的输出永远是合法 JSON（NaN/Infinity 会被替换成 `null`），管道提前关闭（如 `… | head -1`）也不会抛 traceback。

### 10.2 MCP（给 AI 客户端用）

在 WorkBuddy / Claude Code / DeepSeek-Honey 这类客户端的 MCP 配置里加：

```jsonc
{"mcpServers": {"bili-transcriber": {
  "command": "C:\\Program Files\\Bili Note\\bili-transcriber.exe",
  "args": ["--mcp"]}}}
```

配好后可以直接对 AI 说「把这个链接转成文字稿」，它会自己调工具完成。

MCP 提供 9 个工具：`transcribe` / `wait_jobs` / `job_status` / `list_jobs` / `get_transcript` / `cancel_job` / `prewarm_model` / `get_settings` / `update_settings`。

MCP 服务被设置页关掉时的表现：进程**不进入协议循环**直接退出（码 1），原因写 stderr，stdout 保持干净 —— 客户端会显示「服务启动失败」，把这行 stderr 贴出来就能定位。

服务端还做了两件兼容：`resources/list` / `prompts/list` 回空清单（而不是 `-32601`），避免个别客户端把整个服务标成不可用；所有非协议输出（含第三方库的 print）都被改道 stderr，不会污染 JSON-RPC 通道。

细节见 [ai-integration.md](ai-integration.md)。

## 11. 常见问题

**Q1：下载或解析失败怎么办？**

平台接口变化很频繁。第一步永远是升级下载器：

```powershell
.venv\Scripts\pip install -U yt-dlp
```

打包版无法单独升级 yt-dlp，需要等新版本发布。

**Q2：抖音 / YouTube 提示需要登录或访问受限？**

去设置页配「浏览器 Cookie」（先在对应浏览器登录目标网站），或者导出 `cookies.txt` 填路径。YouTube 还要配代理。

**Q3：转写很慢？**

三个原因，逐个排：

1. 没装 GPU 加速包 → 实际在跑 CPU。检查 `%LOCALAPPDATA%\Bili Note\gpu\` 里有没有 DLL。
2. 首次运行在下载模型（1.6 GB）。日志里能看到下载进度，之后不再下载。
3. 模型选太大。Qwen 1.7B 在 CPU 上是 0.6B 的 3 倍耗时。

**Q4：报 `CUDA out of memory`？**

计算精度改 `int8`（显存占用减半），或换小模型（`medium` / `Qwen3-ASR-0.6B`）。

**Q5：唱歌 / 纯音乐视频没有字幕？**

VAD 只识别人声。程序会自动关 VAD 重试一次；重试还空，说明视频确实没人声。

**Q6：设置页「检测模型」提示缺失文件？**

模型包不完整（下载中断过）。删掉那个模型目录，让程序重新下载。

**Q7：端口 8765 被占用？**

`BILI_PORT=9000` 换端口。

**Q8：关了窗口，任务还在跑吗？**

在。程序退到系统托盘继续转写。托盘图标右键「打开主窗口」可以回来。

**Q9：能同时跑多个任务吗？会互相影响吗？**

能。下载 / 转码并发（默认 2 路），转写串行。不会互相影响 —— 转写用锁保护，同一时刻只有一个任务占显卡。

**Q10：重跑会重新下载吗？**

不会。音频和 WAV 缓存命中就跳过。除非你手动删了中间产物。

**Q11：任务列表里出现「running」是什么意思？**

意思是这条任务**已经在队列里或正在跑**，程序没有把它重复入队。命令行 / MCP 重复提交同一个视频时会返回 `running` 而不是再插一条，避免两个 worker 抢同一份中间文件。

**Q12：输出到 `D:\个人用` 这种非程序目录可以吗？**

可以，填绝对路径即可。设置保存时会做**写探针** —— 实际尝试创建目录并写一个临时文件，所以配错了当场就会告诉你，不会等到转写完才发现写不进去。

## 12. 故障排查

### 12.1 按顺序看这三处

1. **任务页下方日志** — 最近的错误就在这。
2. **`%LOCALAPPDATA%\Bili Note\logs\app.log`** — 完整日志，含堆栈（2 MB 轮转，保留 3 份）。
3. **任务行的错误信息** — 鼠标悬停或看行内文字。

### 12.2 具体症状对照

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 双击没反应 | 已有实例在跑 | 检查托盘图标 |
| 浏览器打开是空白 | 端口被占 / 服务未起来 | 换端口，看控制台输出 |
| 下载卡在 0% | 网络 / 需要 Cookie / 需要代理 | 配 Cookie 或代理 |
| 转写一直 `transcribing` 不动 | 模型加载中（首次）或显存爆了 | 等；或降精度重跑 |
| 任务一直 `queued` | 所有工作线程都在忙 | 等一下；或重开应用触发恢复 |
| 模型下载失败 | 镜像站不可用 | 设 `HF_ENDPOINT=https://huggingface.co` 走官方源 |
| SSL 证书报错 | 系统证书链问题 | 程序启动时已内置自愈，一般无需处理 |
| GPU 包装了但没生效 | 解压层级不对（被压平或多套了一层） | 确认存在 `gpu\nvidia\cublas\bin\cublas64_12.dll` |
| 产物写不进去 | 目录权限 / 杀软 | 换输出目录；原子写有重试，但杀软锁定太久也会失败 |
| CLI 一跑就退，提示通道已在桌面端设置中关闭 | 设置页关掉了 CLI 开关 | 设置页勾回来保存；或把 `enable_cli` 改 `true` |
| AI 软件里这个 MCP 服务一直「连接失败」 | 同上（MCP 开关被关）/ 客户端用错命令 | 看 stderr 里的原因；确认配置是 `xxx.exe --mcp` |
| AI 调 `update_settings` 报「不支持修改的设置项」 | 改的是 `enable_cli` / `enable_mcp` | 这两个只能在桌面端改，属预期行为 |
| 桌面端和 AI 同时干活时报 `database is locked` | 旧版本没有等锁 | 0.1.40 起已加 5 秒 `busy_timeout`，请升级 |

### 12.3 完全重置

如果状态乱了想从头来：

1. 关程序（托盘 → 退出）。
2. 删 `data/history.db`（历史索引）和 / 或 `data/settings.json`（设置）。
3. 重开。

**不要删 `data/` 之外的东西** —— `output/` 里是你的产物。

模型放在 `%LOCALAPPDATA%\Bili Note\models`，删了要重下 1.6 GB，一般不需要动。

## 13. 隐私与数据位置

### 13.1 什么会联网

只有两件事：

1. **首次下载模型** — 走 `hf-mirror.com` 国内镜像。
2. **获取视频本身** — 和你用浏览器看视频是同一件事。

转写**不调用任何外部 AI API**。音频和文字内容不会离开你的机器。

### 13.2 数据存在哪

| 内容 | 位置 |
|---|---|
| 设置 | `data/settings.json` |
| 历史索引 | `data/history.db` |
| 运行日志 | `%LOCALAPPDATA%\Bili Note\logs\app.log`（轮转，保留 3 份） |
| 上传的临时副本 | `uploads/`（不会自动清理） |
| 模型 | `%LOCALAPPDATA%\Bili Note\models` |
| GPU 运行库 | `%LOCALAPPDATA%\Bili Note\gpu` |
| 产物 | 设置里的「输出目录」 |

### 13.3 Cookie 怎么被使用

如果你配了浏览器 Cookie 或 cookies.txt，程序只在**下载视频**时把它交给 yt-dlp，用于向平台证明「这个请求是已登录用户发的」。

Cookie **不会**被写进日志、不会被打包、不会被发往除目标平台之外的任何地方。

不配也能用 —— 只是抖音精选、部分 YouTube 这类需要登录的内容会失败。
