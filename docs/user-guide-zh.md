## 1. 这是什么

把 B 站（以及抖音 / 小红书 / 快手 / YouTube）的视频，变成**带时间戳的文字稿**。

一次任务做五件事：解析链接 → 下载音频 → 转成 16 kHz WAV → 本地转写 → 写出 SRT / TXT / Markdown。

关键点：

- **纯本地**。音频不上传，转写在你自己的显卡或 CPU 上跑。
- **可以不要界面**。命令行与 MCP 都能用（AI 客户端可直连）。
- **产物是文件**，不是锁在数据库里的东西 —— 你能直接用、直接改、直接丢给别的工具。

## 2. 安装

### 2.1 选一种形态

| 你想要 | 选这个 |
|---|---|
| 正常安装、开始菜单里点开 | 安装版（`setup.exe`） |
| 不装、解压就用、能放 U 盘 | 便携版（`portable.zip`） |
| 临时用一次 | 单文件版（`single.exe`） |
| 装进自己的 Python 环境 | wheel |

### 2.2 系统要求

- Windows 10 / 11（x64）
- 内存 8 GB 起
- 显卡可选：有 NVIDIA GPU 会快很多，没有也能用

### 2.3 首次启动会慢

双击后要**等 10~20 秒**窗口才出来 —— 程序在导入 torch、transformers 这些大库。
这期间请不要再双击（第二次会被单实例保护拦下，把第一个窗口提到前台）。

### 2.4 启动形态

默认独立窗口（内置 WebView2）。想退回浏览器界面：

```powershell
$env:BILI_FORCE_BROWSER = "1"
bili-transcriber.exe
```

其余开关：`BILI_FORCE_NATIVE=1`（强制窗口）、`BILI_NO_BROWSER=1`（不自动开浏览器）。

## 3. 第一次转写

1. 打开程序，进「任务」页。
2. 把 B 站链接粘到输入框（单 P、多 P、合集、短链都认）。
3. 点「开始转写」。
4. 等状态走完：`下载中 → 转码中 → 转写中 → 保存中 → 完成`。

第一次会下载模型（约 1.5 GB，走国内镜像），之后就离线可用。

产物在「设置」里的**输出目录**。默认是程序目录下的 `output/`，建议改成自己的盘（比如 `D:\我的转写`）。

## 4. 任务页

### 4.1 三种输入

| 输入 | 例子 |
|---|---|
| B 站链接 | `https://www.bilibili.com/video/BV1xx411c7mD` |
| 多 P / 合集 | `.../video/BV1xx411c7mD?p=3`、合集页链接 |
| 本地文件 | `D:\录音\周会.m4a`（拖进去也行） |

### 4.2 队列怎么跑

- 下载与转码可以并行（设置里「并发任务数」1~6）。
- **转写永远串行** —— GPU 一次只能跑一个，排队反而更稳。
- 每行显示：阶段、进度、耗时、失败原因（真实报错，不是"转写失败"四个字）。

### 4.3 暂停 / 继续 / 取消

- 「暂停」：当前这条停下来，队列保留。
- 「继续」：从断点接上（已下载的音频复用）。
- 「取消」：丢掉任务，已生成产物保留。
- 程序重启后，暂停的任务会自动恢复到队列。

### 4.4 运行日志

页面下方实时滚动。排障先看它 —— 它会写清楚卡在哪一步、真实错误是什么。

## 5. 历史页

- 所有任务进 SQLite（`data/history.db`），主键是平台内媒体 ID。**同一条视频重跑会覆盖旧记录**，不会堆重复。
- 可以按标题、UP 主、平台筛。
- 点开能读产物、打开输出目录、看当时用的参数。
- 搜索框搜的是**标题**。要搜转写稿正文，用 `--grep` 或 AI 的 `search_transcript`。
## 6. 设置页逐项说明

按「会不会影响转写结果」排序：

### 6.1 选模型（影响准确率与速度）

| 设置 | 取值 | 怎么选 |
|---|---|---|
| 识别引擎 | whisper / qwen3-asr / sensevoice | 默认 whisper；中文长讲座试 qwen3-asr；机器弱用 sensevoice |
| Whisper 模型 | tiny / base / small / medium / large-v3 / large-v3-turbo | 默认 large-v3-turbo，是准确率与速度的平衡点 |
| 设备 | auto / cuda / cpu | auto 优先 CUDA，检测不到就回落 CPU |
| 计算精度 | auto / float16 / int8_float16 / int8 | 显存不够（OOM）就往下调 |
| 语言 | auto / zh / en | 明确知道语言就填，比 auto 更快更准 |
| VAD 静音过滤 | 开 / 关 | 长视频开着明显省时间；音乐类内容建议关 |

### 6.2 产物相关

| 设置 | 说明 |
|---|---|
| 输出目录 | 产物落地处。相对路径会被解析成绝对路径，避免不同进程 CWD 不同导致产物乱跑 |
| 保留音频 | 开着会把 16 kHz WAV 留在输出目录；关掉转完即删 |
| 图文讲义 | 开启后 B 站任务会额外下视频流做关键帧截图，产出 `*.notes.md` + `*_frames\` |
| 模型目录 | 默认 `%LOCALAPPDATA%\Bili Note\models`。模型可手动放进去，程序不重复下载 |

### 6.3 网络与外部访问

| 设置 | 说明 |
|---|---|
| 浏览器 Cookie | 从哪个浏览器读登录态 |
| cookies.txt | 文件路径，**优先级高于浏览器 Cookie** |
| 网络代理 | 形如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080` |
| 并发任务数 | 下载/转码并行度，1~6，默认 2 |

### 6.4 外部调用通道

| 设置 | 关掉后会怎样 |
|---|---|
| 允许命令行（CLI）调用 | `bili-transcriber-cli` 与 `--cli` 立即退出，退出码 3 |
| 允许 MCP 调用 | `--mcp` / `--mcp-http` 写一条 stderr 并返回 1，stdout 保持空 |

> 这两个开关**只能在这里改**。CLI 与 MCP 自己改不了 —— 防止被提示注入的 AI 打开或关掉自己的通道。

## 7. 网络与登录（Cookie / 代理）

### 7.1 三步流程

设置页这一节有四个东西：三个输入框 + 三步流程。

**推荐用法一句话：点「一键检测」→ 看它自动填好 → 点「② 测试连接」→ 点「③ 保存设置」。**

### 7.2 一键检测做了什么

约 5~8 秒内并行做三件事：

1. **扫浏览器** —— 枚举本机 Chromium 系与 Firefox，看你在哪些平台有登录态。
   这一步只读 Cookie 的**域名、名字、有效期**，不碰 Cookie 值。
2. **找 cookies.txt** —— 在程序目录、`data/`、下载、桌面、文档里搜名字带 cookie 的 `.txt`。
3. **探网络** —— 各平台直连延迟；系统代理、环境变量代理、常见本机端口（7890 / 7897 / 10809 / 1080…），
   并验证哪个代理真能访问 YouTube。

结束后按「覆盖平台数」挑最优来源**自动填进三个框**；识别不到就保持你原来的值，绝不清空。

### 7.3 「检测」和「测试连接」有什么不同

| | 一键检测 | ② 测试连接 |
|---|---|---|
| 联网 | 探测平台可达性 | 同样探测，但**用你当前填的代理** |
| 读 Cookie | 只读元信息（名字 / 有效期） | 真读 Cookie 值 |
| 能回答 | 「应该填什么」 | 「现在这套配置能不能用」 |

B 站会调官方接口做真登录校验，**能显示你的账号名**；抖音 / 小红书 / 快手接口需要额外签名，
只确认登录 Cookie 存在。

### 7.4 Chrome 127+ / Edge 的 Cookie 是「应用绑定加密」

Chrome 127 起把 Cookie 换成 **App-Bound Encryption（v20）**：密钥由浏览器 elevation 服务包裹，
**只有浏览器本体、在原始配置路径上**才能解开。第三方解密实现（yt-dlp 等）只认老的 v10。

本程序的做法：让浏览器自己解密 —— 复制最小配置到临时目录，起一个**无窗口临时实例**（用完即杀、目录删掉），
经调试协议取回明文。

| 你看到的 | 含义 | 该做什么 |
|---|---|---|
| 绿点「已登录」+「值加密读不到」 | 登录态在，值取不出 | 关掉浏览器再点「测试连接」，或点「导出」 |
| 锁图标「读取失败」 | Cookie 库被独占，连名字都读不到 | 关掉浏览器重测，或改用 cookies.txt |
| 「值加密读不到」但下载正常 | 已自动落临时 cookies.txt（10 分钟缓存） | 无需操作 |

> 实测：Chrome 运行时 Cookie 库在 Windows 上**完全不可复制**（`PermissionError 32`，
> 30 秒 60 次尝试全失败）。这是 Chrome 的安全设计，不是程序卡住 —— 关掉浏览器一次就成。

### 7.5 三种来源怎么选

1. **浏览器 Cookie（最省事）** —— 直接读登录态。缺点是浏览器**开着**时库被独占。
2. **cookies.txt（最稳）** —— 优先级最高，不受浏览器开关影响；可用「从浏览器导出 cookies.txt」一键生成。
3. **都不用** —— 只下公开内容，B 站普通视频足够。

> 导出的 cookies.txt 含登录凭据，只在 `data/` 下，不要分享或提交。

### 7.6 什么时候真的需要 Cookie / 代理

| 平台 | 需要 Cookie? | 需要代理? | 说明 |
|---|---|---|---|
| B 站 | 多数不需要 | 不需要 | 1080P+ / 大会员 / 部分番剧要登录态 |
| 抖音 | **建议要** | 不需要 | 未登录常被风控 |
| 小红书 | **建议要** | 不需要 | 登录后才返回完整地址 |
| 快手 | 一般不需要 | 不需要 | 走分享页解析 |
| YouTube | 部分需要 | **必须** | 年龄限制 / 会员视频要登录；境内需代理 |
## 8. 输出产物怎么读

一次任务最多四个文件（另加一个图目录）：

| 文件 | 用途 |
|---|---|
| `标题.md` | 带元信息（平台 / UP 主 / 时长 / 来源 / 引擎 / 时间）与逐段正文 —— 推荐阅读与引用 |
| `标题.txt` | 纯文本，喂 AI 最省 token |
| `标题.srt` | 标准字幕，可直接给播放器 |
| `标题.notes.md` | 只有开了「图文讲义」才有：段落 + 关键帧截图 |
| `标题_frames\` | 讲义配图（`slide_001.jpg` …） |

正文是**逐段**的，一段一个时间戳：

```markdown
[00:12] 先从两阶段提交说起……
[00:31] 它解决的是"部分失败"下的原子提交问题
```

合集/多 P：同一合集共享一个输出目录，单 P 用 `_P01` / `_P02` 后缀区分。

## 9. 命令行怎么用

### 9.1 最常用三条

```powershell
bili-transcriber-cli "https://www.bilibili.com/video/BV1xx411c7mD"     # 转一条
bili-transcriber-cli --grep "关键词" --context 400                      # 全库检索
bili-transcriber-cli --result BV1xx411c7mD --format md --max-chars 0    # 读已生成的产物
```

源码模式等价写法：`.venv\Scripts\python -m app.cli ...`。

### 9.2 打包 exe 要注意

`bili-transcriber.exe` 默认进**图形界面**。要走命令行必须加 `--cli`：

```powershell
bili-transcriber.exe --cli --doctor
bili-transcriber.exe --cli "BV1xx411c7mD" --json
```

（源码模式 `python -m app.cli` 天然是 CLI，不需要这个开关。）

### 9.3 全部参数

完整 34 个选项见 [README 的命令行参考](../README.md#命令行参考)，
或用 `--help` 现查。

### 9.4 输出编码

被管道 / 重定向接管时一律 UTF-8（AI 按 UTF-8 解析不会乱码）；
留在终端里则沿用控制台代码页，避免 `cmd.exe` 花屏。

## 10. 让 AI 用起来

### 10.1 先自检

```powershell
bili-transcriber-cli --doctor
```

它会告诉你：本机装了哪些 AI 客户端、配置文件在哪、MCP 入口是否可用。

### 10.2 一条命令写入配置

```powershell
bili-transcriber-cli --agent-config workbuddy --write
bili-transcriber-cli --agent-config codex --write
bili-transcriber-cli --agent-config claude --write
```

写前自动备份 `.bak`，只动 `bili-transcriber` 一个条目。
**DSH 例外**：连接表由界面托管，程序拒绝直写，会给你一段可粘贴的配置。

### 10.3 只能连 URL 的客户端

```powershell
bili-transcriber-cli --mcp-http 8765
```

客户端配 `http://127.0.0.1:8765/mcp`。要鉴权就设环境变量 `BILI_MCP_HTTP_TOKEN`，
请求带 `Authorization: Bearer <token>`。

### 10.4 AI 能做什么

11 个工具：转写、等待、查状态、列任务、取产物、**全文检索**、**网络与 Cookie 体检**、取消、预加载、读写设置。

典型对话：

```text
你：我的 Cookie 和代理现在能用吗？
AI：调 check_network mode=test → 逐平台返回延迟与登录态

你：把这个视频转成文字，找出讲"一致性"的部分
AI：transcribe → wait_jobs → search_transcript → 给出时间戳与原文
```

> `check_network` 的 `test` 档会读你当前设置，结论和你在设置页点「测试连接」一致。

## 11. 常见问题

**窗口没出来 / 点了没反应**
等 10~20 秒。仍然没有就看日志：`%LOCALAPPDATA%\Bili Note\logs\app.log`。

**开几分钟自己退出**
0.1.40 及更早的已知问题（pywebview 临时目录被回收）。0.1.41 起已修，升级即可。

**B 站只有 480P**
需要登录态：配浏览器 Cookie 或 cookies.txt。

**转写慢**
确认真的用上 GPU（设置「设备」= `cuda`，`--doctor` 看探测结果）。
CPU 上 large-v3-turbo 慢 3~10 倍；换 `small` 或 SenseVoice 会明显快。

**下载报「需要 Cookie」但测试连接是通过的**
检查 `data\` 下有没有 `.cookies-from-<浏览器>.txt` 缓存（10 分钟有效）。
浏览器后来关掉又重新打开会刷新缓存；实在不行点「导出 cookies.txt」并填路径。

**多 P 里一 P 失败会不会全重来**
不会。每条独立状态，已完成的不会重下。

**能不能不装界面**
可以。wheel 安装后直接用 `bili-transcriber-cli`，或用 MCP 交给 AI。

**端口被占**
设 `BILI_PORT=9000` 换个端口。重复双击只会把已有窗口提到前台，那是正常的单实例保护。

## 12. 数据与隐私

| 数据 | 位置 |
|---|---|
| 设置 | `data/settings.json` |
| 历史 | `data/history.db` |
| 模型 | `%LOCALAPPDATA%\Bili Note\models` |
| 日志 | `%LOCALAPPDATA%\Bili Note\logs\app.log`（2 MB 轮转，留 3 份） |
| 产物 | 设置里的输出目录 |
| 导出的 cookies.txt | `data/cookies.txt`（**含登录凭据**） |

外部请求只有两种：下载视频/音频、下载模型。日志、历史、产物都在本机，不会上传。

> Cookie 只在下载那一刻交给 yt-dlp，不进日志、不打包、不发往第三方。
