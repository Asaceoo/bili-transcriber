本版本主线是**给桌面工具加上 AI 调用能力**（CLI + MCP），并对这套新代码完成第三轮对抗性审查（工具实现者 / 审查者 / AI 使用方三视角，多轮迭代收敛）。所有修复均以真实运行报错为依据，全量测试 **346 项通过**，真机验证通过。

## 新功能

### CLI：命令行调用

新增 `bili-transcriber-cli`，26 个参数覆盖提交、查询、产物读取、设置管理、模型预热：

```bash
bili-transcriber-cli "https://www.bilibili.com/video/BVxxx" --json
bili-transcriber-cli --list --status-filter done --json
bili-transcriber-cli --result BV1xx411c7mD_p1 --format md
bili-transcriber-cli --set engine=whisper --set device=cuda
```

### MCP：AI 客户端直连

`bili-transcriber.exe --mcp` 以 stdio 方式提供 9 个工具，WorkBuddy / Claude Code / DeepSeek-Honey 等客户端可直接调用：
`transcribe` / `wait_jobs` / `job_status` / `list_jobs` / `get_transcript` / `cancel_job` / `prewarm_model` / `get_settings` / `update_settings`。

### 服务层重构

新增 `app/headless.py` 作为 CLI 与 MCP 的**唯一业务入口**，两条通道行为完全一致，只有传输方式不同。同时新增 `app/paths.py` 保证 GUI / CLI / MCP 指向同一份 `data/`（否则 AI 调用看不到桌面端的历史与设置）。

## 修复

### 编码与序列化
- **修复打包 exe 的 CLI 输出崩溃**：窗口态 exe（`console=False`）复用父进程管道，`sys.stdout.encoding` 取系统 ANSI 代码页（中文 Windows = GBK），`print('🎉')` 直接抛 `UnicodeEncodeError`。现按 stdout 实际编码探测，不可表示时降级 `ensure_ascii=True`，并兜一层 `backslashreplace`。复验：GBK 环境下输出 211 字节，UTF-8 解析正常，标题中的 emoji 完整保留。
- **修复 NaN 破坏 JSON 解析**：`json.dumps` 默认 `allow_nan=True` 会写出裸 `NaN` / `Infinity`，JS 侧 `JSON.parse` 直接失败。现所有 MCP / CLI 出站统一过 `json_safe()` + `allow_nan=False`。

### 任务调度
- **修复重复提交导致双重入队**：对已在处理中的任务再次提交时，原实现会再插一条队列记录，两个 worker 抢同一任务，一个删了 wav 另一个就 `FileNotFoundError`。现引入 `_scheduled` 集合作为唯一裁决点，命中即返回 `status: running` 而不入队。
- **修复 `--no-wait` 任务变成僵尸**：CLI 提交后进程退出，任务永久停在 `transcribing`，桌面端再也不理它（原恢复逻辑只认 queued / paused）。现恢复**全部** `ACTIVE_STATUSES`。复验：续跑后 `done`，产物 `.md` 正常落盘。
- **修复启动恢复自身造成重复入队**：恢复逻辑与 `submit_prepared` 的 `start()` 叠加导致同一任务被排两次。现 `submit_prepared` 仅在有新 queued 时才 `start()`。
- **修复两个实例并行处理同一任务**：真机跑出两份「恢复上次未完成的任务:1 个」日志，后一个因 wav 被前一个删除而崩。现加 `CreateMutexW` 单实例保护（name 含 `data/` 路径哈希，不同数据目录仍可并行），第二个实例打开已有窗口后自行退出。复验：第二个进程提示「检测到已有实例在运行」退出，第一个实例 HTTP 200 正常服务。

### 设置校验
- **修复非法设置被静默持久化**：实测接受 `device=gpu`、`engine=whisper-large`、`output_dir=Z://no-such-drive//out` 并全部写进 `settings.json`，下次启动才炸。现 `_validate_settings()` 做引擎 / 设备白名单校验，输出目录**写探针**（实际创建目录并写临时文件）。复验：`output_dir` 非法时明确拒绝并给出 `[WinError 5] 拒绝访问` 原因。

### 落盘可靠性
- **修复产物可能的半截文件**：`write_text` 被杀软或已打开的文件锁定时直接失败。现改为 `.tmp` + `os.replace` 原子写，配 6 次 `PermissionError` 线性退避。
- **修复日志初始化在无 stderr 环境崩溃**：`sys.stderr is None` 时不挂 StreamHandler。

### MCP 协议层
- **修复批量请求丢失响应**：客户端发 JSON 数组时只回最后一条。现逐条处理并展平为响应数组。
- **修复参数类型不可靠**：AI 客户端常把 `limit` 传成字符串。现 `_arg_int` / `_arg_num` / `_pick` 容错转换。
- **修复无管道启动时的怪异崩溃**：`console=False` 且无管道时 `sys.stdin` 为 `None`，`readline()` 抛 `AttributeError`。现 `_reopen_null_streams()` 写明确日志并非零退出。

### 命令行细节
- **修复 `--prewarm` 是空操作**：CLI 是一次性进程，`close()` 立刻打断加载线程。现 `prewarm(wait=True)` 阻塞到加载结束，退出码反映真实 `loaded` 状态。
- **修复 `--set workers=abc` 静默通过**：现抛 `ServiceError("--set workers 需要整数:abc")`。
- **修复 `wait()` 死等超时**：无 worker、队列空、却有 queued 任务时，原实现干等到超时。现返回 `{"stalled": true, "hint": ...}` 明确告知「任务处于排队态但本进程未在调度它」。

### 文档准确性（重写时逐条对照源码核实，修掉 3 处历史错误）
- **GPU 加速包解压路径写错**：旧文档称「`gpu\` 下应直接看到 `cudnn*.dll`」，实际 zip 保留 `nvidia/{cublas,cudnn,cuda_runtime,cuda_nvrtc}/bin/` 结构，`gpu_runtime._dll_root()` 也按此定位。按旧文档压平解压会找不到 DLL、GPU 静默不生效。现明确「照原样解开，不要压平」并给出校验路径 `gpu\nvidia\cublas\bin\cublas64_12.dll`。
- **日志路径写错**：旧文档写 `data/logs/`，实际是 `%LOCALAPPDATA%\Bili Note\logs\app.log`（2 MB 轮转、保留 3 份）。
- **合集输出目录归属写错**：旧文档称「每个分 P 各自独立目录」；实际 `info.bv` 已剥掉 `_p2` 后缀，同一合集的分 P **共享一个目录**，靠文件名 `_P01` / `_P02` 后缀区分。技术手册新增《输出目录与文件名规则》一节说明这套命名契约。

## 已知限制

- MCP 仅实现 JSON-RPC 子集（`initialize` / `tools/list` / `tools/call` / `ping`），不支持 resources / prompts / sampling。
- GPU 提速仍只覆盖 whisper（ctranslate2）；Qwen3-ASR 走 torch，SenseVoice 走 onnxruntime CPU。
- 打包版内 yt-dlp 无法单独升级，平台接口变更需等新版本。
