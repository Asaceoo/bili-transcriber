# v0.1.42 — 网络与 Cookie 一键检测

## 三个按钮

```
① 检测        找到浏览器 Cookie / cookies.txt / 可用代理,自动填进输入框
② 测试连接    逐平台实测:网络通不通、Cookie 有没有登录、B 站账号是谁
③ 保存设置    写入 settings.json,立即生效,不用重启
```

**检测只填更优的值**：如果某个输入框你手填过内容，检测发现自动结果不如它，就不动；检测失败也不会把已有配置清空。

## 检测都做了什么

| 来源 | 怎么找 | 读到什么 |
|---|---|---|
| 浏览器 Cookie | 扫 Chrome / Edge / Brave / Chromium / Firefox 的 Cookie 库 | 只有 `域名 + 名字 + 过期时间`，**不解密 Cookie 值** |
| `cookies.txt` | 项目目录、`data/`、下载、桌面、文档、输出目录 | Netscape 7 列格式，支持 `#HttpOnly_` 前缀 |
| 代理 | 注册表 `ProxyEnable/ProxyServer` → `HTTPS_PROXY` 等环境变量 → 常见端口 TCP 探测 | 探测到的候选再拿 YouTube 验证一次才认 |

平台登录态按「登录 Cookie 名」判断：B 站 `SESSDATA`、抖音 `sessionid`、小红书 `web_session`、快手 `kuaishou.server.web_st`、YouTube `SAPISID`。

**为什么只读元信息就够**：判断"这个平台登没登录"只需要知道那条 Cookie 在不在、过没过期，不需要它的值。解密要动 DPAPI 主密钥，属于不必要的风险面，所以这里刻意不做 —— 真要下载带 Cookie 的内容时，交给 yt-dlp 自己去读浏览器。

## 为什么浏览器开着就"读不到"

Chrome / Edge 运行时会**独占锁住** Cookie 数据库，`shutil.copy2` 直接抛：

```
PermissionError: [WinError 32] 另一个程序正在使用此文件，进程无法访问。
```

Win32 `CreateFileW` 带共享标志去读，同样是 `err=32`。这不是 bug，也不打算绕过 —— 所以检测会明确告诉你：

> Chrome、Edge 正在运行，Cookie 库被独占，关掉浏览器后重新检测，或改用 cookies.txt

想边用浏览器边下载带 Cookie 的内容，就走 `cookies.txt`（检测页有「导出」按钮，从浏览器直接导一份）。

## 测试连接：逐平台实测

点「② 测试连接」后，每个平台一行：

```
B站        323 ms   ✓ 已登录(已校验)  账号: xxx
抖音       242 ms   · 未登录           仅能下载公开内容
YouTube    738 ms   · 未登录           仅能下载公开内容
```

- **延迟**：真发一个 HTTP 请求量的，不是 ping
- **已登录(已校验)**：拿 `SESSDATA` 调 `api.bilibili.com/x/web-interface/nav`，`code==0 && isLogin` 才算数，并把 `uname` 显示出来
- **已登录**：只确认 Cookie 存在，没做在线校验（抖音/小红书接口要签名，硬校验不划算）
- **读取失败(锁图标)**：浏览器正在运行
- **来源**：这次测试用的哪个 Cookie 来源，避免"我明明填了怎么没用"

## 帮助与动效

四组折叠帮助，都在设置页里，不用翻文档：

- **各平台到底需不需要 Cookie / 代理?** —— 六行表格：B 站多数不用、抖音/小红书建议要、快手不用、YouTube 必须代理

- **检测结果 / 测试结果怎么看?** —— 每个徽章什么意思
- **下载失败的常见原因** —— 四条最常见的报错对应怎么修

动效保持在"能感觉到但不打扰"的程度：结果淡入上浮、徽章依次弹入（每行错开 40–50ms）、检测时按钮图标旋转 + 提示呼吸、步骤条随进度点亮。全部走 `@media (prefers-reduced-motion: reduce)` 关掉，开了系统"减少动态效果"就只剩静态。

## 性能：13.8 秒 → 5~8 秒

第一版检测要 13.8 秒，慢在两个地方，都改了：

**① `socket` 的 timeout 是"每个地址、每次操作"，不是总时长。**

被墙的域名解析出多个 IP，urllib 会逐个连、逐个等 —— YouTube 配 3.5s 实测等了 7.2 秒。改成 `future.result(timeout=…)` 做**硬截止**，到点就返回"超时"，后台线程留给它自己跑完（`pool.shutdown(wait=False)`）。

**② 直连探测必须先关掉环境变量代理。**

```python
opener = urllib.request.build_opener(urllib.request.ProxyHandler({}))
```

urllib 默认 opener 会读 `HTTPS_PROXY`。本机开着 Clash 时，"直连"其实走了代理、结果全程撒谎 —— 明明直连不通却报"直连正常"。显式传空 `ProxyHandler({})` 才是真直连。

顺带两个护栏：DNS 单独给 2 秒上限；**走代理时不解析本地 DNS**（socks5h 由代理解析，本地 DNS 污染不该影响代理可用性判断）。

现在实测 **5.3～7.9 秒**（取决于 YouTube 是否超时），代理扫描和直连探测并发跑。

## 其他改进

- **`netcheck.py`（1074 行）独立成模块**：检测、解析、探测、测试、导出五块能力，UI 只负责画。这样 CLI/测试可以直接调，不依赖界面。
- **`native_dialog.pick_file()`**：原来只有多选版本，Cookie 文件是单选，抽了 `_open_dialog()` 出来复用，新增 `COOKIE_FILTER`。
- **导出 Cookie 到 `data/`**：`export_browser_cookies()` 走 yt-dlp 的 `--cookies-from-browser`，落成 Netscape 文件，提示里写明"内含登录凭据，只存本机"。
- **设置页卡片宽度 `max-w-lg` → `max-w-3xl`**：512px 装不下三行徽章 + 两列说明，内容被挤成两行看不全。
- **步骤条未激活态加灰**：原来只调透明度，深色文字仍然显眼，远看跟激活态分不清。
- **应用内常见问题补两条**：抖音/小红书要登录吗、YouTube 打不开怎么办。

## 踩过的坑

**Quasar 的 `loading` 属性会吃掉按钮文案。** 检测时给按钮加 `props("loading")`，结果按钮变成一个空白粉块，只剩转圈 —— 用户根本看不出在干什么。改成 `set_text("正在检测…") + props("disable")`，`finally` 里恢复原文案。

**Quasar 页签点不动（自动化测试里）。** `locator.click()` 和 `page.evaluate(() => tab.click())` 都改不了 `aria-selected`，Quasar 的 tab 只认真实指针事件。最后用 `page.mouse.click(中心坐标)` 才切得过去 —— 这是自动化脚本的坑，真机上没影响。
