## 新功能

### 1. CLI / MCP 通道开关

设置页 →「AI 调用与命令行」，两个开关默认开启：

| 开关 | 关掉之后 |
|---|---|
| 允许命令行（CLI）调用 | `--cli` 直接拒绝，输出 `{"ok": false, "error": "…已在桌面端「设置」中关闭"}`,退出码 **3** |
| 允许 MCP 调用 | `--mcp` 不进入协议循环，原因写 stderr，退出码 **1**，stdout 保持干净 |

设计上做了三条约束：

- **只影响新进程**。已在连接的 AI 客户端需重连；桌面端永远可用。
- **只能从桌面端改**。`--set enable_cli=false` 与 MCP 的 `update_settings` 都被拒绝，提示「请在桌面端设置页修改」—— 被提示注入的 AI 不能给自己开门。
- **拒绝发生在建 Service 之前**。通道关闭时连数据库都不打开，不白占一把 SQLite 锁。

同一区块还有「MCP 客户端配置」折叠面板：展开即可复制 `mcpServers` 片段，命令路径按当前形态自动填（打包版 `xxx.exe --mcp`，源码模式 `python -m app.mcp_server`）。

### 2. `get_settings` 如实报告

`transcribe(engine=…)` 这类覆盖只在本进程生效、不写盘。以前 `get_settings` 会回显被覆盖后的对象，AI 据此会说「我已把你的引擎改成 sensevoice」；现在它报**磁盘上的真相**，本次覆盖单列在 `session_overrides` 里。

### 3. `set_settings` 改成读-改-写

长驻的 MCP 进程原本会用它启动时的内存副本覆盖整个 `settings.json`。用户刚在设置页关掉 MCP、AI 随后调一次 `update_settings(engine=…)`，开关就被悄悄写回来了。现在先重读磁盘、只套用本次改动的键。

## 修复（均以真实运行报错为依据）

| 问题 | 证据 | 修法 |
|---|---|---|
| 桌面端与 AI 同时写库直接失败 | 复现:`busy_timeout=0` 时第二个写者立刻 `OperationalError: database is locked` | `PRAGMA busy_timeout=5000`；实测双写者 3 秒写入 9353 行、零错误 |
| 每次启动多开一个浏览器标签页 | 日志每次都多一行 `__mp_main__: 已有实例在运行,本进程退出` | NiceGUI spawn 的子进程重跑 `main()` 抢不到互斥体就回落「已有实例」分支;先判 `current_process().name != "MainProcess"` 直接放行 |
| 客户端发来非 UTF-8 字节，整个 MCP 会话被拆 | 复现:`\xff\xfe` → `UnicodeDecodeError` 冒泡出 `serve()` | stdin `errors="replace"` + `serve()` 捕获解码/读错误,降级为 `-32700` 响应 |
| 任何遗留 `print` 都会污染 JSON-RPC 帧 | stdio 是一行一个 JSON | `_isolate_stdout()`:协议句柄存局部变量,`sys.stdout` 改指 stderr |
| 客户端无条件拉 `resources/list` 时被判「服务不可用」 | 部分客户端拿到 `-32601` 就整体标记失败 | 回空清单（`resources` / `resourceTemplates` / `prompts`） |
| `cli … \| head -1` 抛 traceback 且退出码变 1 | 脚本会误判成任务失败 | `_write()` 捕获 `BrokenPipeError/OSError/ValueError` 后把 stdout 指向 `devnull` |
| `--set output_dir=` 把空串落盘 | 空值会被解析成程序根目录，产物散落源码树 | 校验层拒绝空目录 |
