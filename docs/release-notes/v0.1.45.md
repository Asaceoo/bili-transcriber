# v0.1.45 — Chrome 127+ 的 Cookie 终于能读了（应用绑定加密 v20）

一句话：**设置页「测试连接」不再把五个平台全报「读取失败」，下载也不再"测试通过、下载报需要 Cookie"。**

## 问题：不是 yt-dlp 版本旧，是 Chrome 换了加密

Chrome 127 起把 Cookie 改成 **App-Bound Encryption（v20）**：密钥由浏览器 elevation 服务包裹，
且**绑定原始 user-data-dir 路径**。yt-dlp 只实现老的 v10，遇到 v20 一律
`Failed to decrypt with DPAPI`（issues/10927）。

实测本机证据：

| 项 | 值 |
|---|---|
| Chrome | 156.0.8078.73 |
| Cookie 密文前缀 | **1674 / 1674 全是 v20** |
| Local State | 有 `app_bound_encrypted_key`（APPB，860 字节） |
| yt-dlp 2026.07.04 | 只认 v10 |

后果有两个，都被这次修掉：

1. **测试连接**把五个平台全标成「读取失败」——包括本来读得到登录态的平台；
2. **下载**仍然走 `cookiesfrombrowser`，一旦浏览器在跑，连库都复制不了
   （`Could not copy Chrome cookie database`）——于是出现"测试通过、下载失败"的自相矛盾。

## 新增：`app/cookiebridge.py` —— 让浏览器自己解密

复制 `Local State` + Cookie 库到临时目录 → 起 `--headless=new` 临时实例 →
**标准库手写 WebSocket** 走 CDP `Network.getAllCookies` → 拿回明文 → 杀进程、删目录。

- 不碰你正在用的浏览器窗口；临时目录用完即删。
- **不引入任何新依赖**（手写 WebSocket），打包体积不变。
- 实测：临时副本上 **1.06 秒**解出 v20 明文，导出的 Netscape 文件能被项目自己的
  `parse_cookie_file()` 读回登录态（闭环）。

## 修复：三处语义错误

| # | 问题 | 修法 |
|---|---|---|
| 1 | 「值读不到」被当成「登录态读不到」，五平台全红 | 三态分开：值 / 元信息 / 锁。元信息在就照实显示 `present` + 「值加密读不到」 |
| 2 | “登录态在”被当成“配置可用”（`report.ok=True`） | 值取不到时 `ok=False`，并提示「识别到登录态但值取不到」——避免绿灯骗人去下载 |
| 3 | 浏览器名不做规范化，`Chrome` / `edge了空格` 静默失效 | 统一 `normalize_browser()`，支持别名；不支持的浏览器给**支持列表**而不是"没找到" |

## 修复：下载链路同步打通

`downloader._cookie_opts()` 现在会把桥接到的明文落成
`data/.cookies-from-<浏览器>.txt`（**10 分钟缓存**）交给 yt-dlp 走 `cookiefile`；
桥接不可用时才退回 `cookiesfrombrowser`。缓存文件在 `data/` 下，已被 gitignore。

## 修复：MCP `check_network(test)` 不读设置

它号称"按当前配置实测"，实际调用 `test_configuration(timeout=)` 时**没传浏览器/Cookie/代理**，
AI 永远只能拿到 `source='未配置 Cookie'`。现在会读 `get_settings()` 并传下去，
结论与桌面端「测试连接」一致。

顺带修：`mode` 只 `lower()` 不 `strip()`，导致 `' test '` 被拒而 `'TEST'` 能过 ——
现在两者等价。

## 已知限制（不阻塞发布）

1. **浏览器开着时仍读不到 Cookie** —— Chromium 独占锁（实测 30 秒 60 次全失败），
   这是浏览器安全设计；关掉浏览器即可，文案已明确告知而不是假装重试。
2. **v20 只能在原始路径解** —— ABE 密钥绑定路径，复制 profile 到别处对 v20 无效。
